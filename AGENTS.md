# vr1e-profile

Self-updating GitHub profile stats card: fetches stats and renders `dark_mode.svg` / `light_mode.svg` at the repo root.

## Commands

- Run everything from the repo root — `writeCards` writes `<mode>_mode.svg` CWD-relative.
- `npm run update` needs `ACCESS_TOKEN` (a GitHub PAT) or it throws.
- `npx tsx src/render-preview.ts` **overwrites the committed SVGs with hardcoded fake stats.** Use it only when you intend to throw the result away, and `git checkout` the SVGs afterwards.
- `npx tsc --noEmit` is the typecheck. No script wraps it and CI doesn't run it — run it before finishing.
- Only `update` and `test` are npm scripts; `src/generate-ascii.ts` and `src/render-preview.ts` are `npx tsx` entry points.

## Gotchas

- `src/ascii.ts` is generated by `src/generate-ascii.ts` — never hand-edit. Regenerating needs the original source photo, **which is not in this repo**, so treat the art as effectively frozen.
- `src/metrics.ts` bakes the art's aspect ratio into `ascii.ts` and drives the renderer's layout. Changing it invalidates the committed art (see above).
- Non-breaking spaces in `src/card.ts` are load-bearing: SVG collapses runs of regular spaces, so `NBSP` (line 60) and the `replaceAll` on the art (line 248) hold the alignment. Don't let a formatter or edit normalize them.
- `typescript` is a devDep but a *runtime* input: `card.ts` reads its version for the card's "Kernel" line. Bumping it changes the rendered output.
- Pushing to `main` under `src/**` or `.github/workflows/update-stats.yml` triggers the workflow, which regenerates the SVGs and pushes an `update stats` commit back to `main`.
