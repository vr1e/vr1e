# vr1e-profile

Self-updating GitHub profile stats card: fetches stats and renders `dark_mode.svg` / `light_mode.svg` at the repo root.

## Commands

- Run everything from the repo root — `writeCards` writes `<mode>_mode.svg` CWD-relative.
- `npm run update` needs `ACCESS_TOKEN` (a GitHub PAT) or it throws.
- `npx tsx src/render-preview.ts` **overwrites the committed SVGs with hardcoded fake stats.** Use it only when you intend to throw the result away, and `git checkout` the SVGs afterwards.
- `npm run typecheck` (`tsc --noEmit`) is the typecheck — run it before finishing; tests run through tsx and won't catch type errors.
- Only `update`, `typecheck`, and `test` are npm scripts; `src/generate-ascii.ts` and `src/render-preview.ts` are `npx tsx` entry points.

## Gotchas

- `src/ascii.ts` is generated by `src/generate-ascii.ts` — never hand-edit. Regenerating needs the original source photo, **which is not in this repo**, so treat the art as effectively frozen.
- `src/metrics.ts` bakes the art's aspect ratio into `ascii.ts` and drives the renderer's layout. Changing it invalidates the committed art (see above).
- Non-breaking spaces in `src/card.ts` are load-bearing: SVG collapses runs of regular spaces, so the `NBSP` const (padding/indentation) and the `replaceAll` on each art line hold the alignment. Don't let a formatter or edit normalize them.
- `typescript` is a devDep but a *runtime* input: `card.ts` reads its version for the card's "Kernel" line. Bumping it changes the rendered output.
- Pushing to `main` under `src/**` or `.github/workflows/update-stats.yml` triggers the workflow, which regenerates the SVGs and pushes an `update stats` commit back to `main`.
- The SVGs are committed build output, so they conflict on nearly every merge, rebase, and stash pop — and one side is often `render-preview`'s fake stats. Never hand-resolve those hunks: take one side wholesale (`git checkout --ours`), then regenerate.
- The card **repaints itself by date** — `paletteFor(now)` in `src/palette.ts` picks one of five palettes: autumn/winter/spring/summer on meteorological boundaries (Mar/Jun/Sep/Dec 1, UTC), overridden by **matrix** (green-on-black) every 10th Monday-aligned epoch week. This is deliberate and undocumented on purpose — the README says nothing about it. Three consequences look like bugs and are not:
  - **The seasons are subtle.** A bolder set with tinted ASCII art and high-chroma grounds was built, rendered head-to-head, and rejected. The art stays untinted (`text` near-white) so all four read as the same card. Don't make them louder.
  - **Matrix uses one `Theme` for both modes**, so a light-mode reader gets a black card, and on GitHub's dark chrome that card has no visible edge (1.11:1). Both known; `border` is dead, so there is nowhere to put an edge anyway.
  - **Matrix alone puts `key` brighter than `value`**, inverting the other four. That inversion is what makes `sparkline()`'s `['dots','plus','value','key','minus']` ramp monotonic — it is the only palette where that ramp reads as a real quiet→busy gradient.
- Because of that repaint, an SVG regenerated in a different week differs on every `fill` with identical stats. A huge colour-only diff or conflict is expected, not a break — regenerate rather than picking a side on merit; neither side's palette is authoritative.
